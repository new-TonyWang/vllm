什么时候需要 Buffer 暂存？

在线量化场景下，NCCL 到达粒度 vs 量化 scale 计算粒度的精确分析

前置：NCCL 到达粒度 vs Fused Param

每次 NCCL 传输到达的是一个 HF checkpoint tensor（如 q_proj），但 vLLM runtime 把多个 HF tensor 融合成一个大参数（如 qkv_proj）。三次传输才凑齐一个 fused param：

  q_proj  [4096, 4096]  ──▶ qkv_proj[0:4096, :]       ┐
  k_proj  [1024, 4096]  ──▶ qkv_proj[4096:5120, :]     ├ 三次传输凑一个 fused param
  v_proj  [1024, 4096]  ──▶ qkv_proj[5120:6144, :]     ┘

问题：在线量化的 scale 什么时候才能算？

取决于量化粒度和 fused param 的关系。

量化 scale 的计算需要看到一定范围的数据。如果这个范围完全落在单次到达的 shard 内，就可以 eager 逐 shard 量化；如果范围跨越多次到达的 shard，就必须暂存等配对。

唯一需要 buffer 暂存的组合 = per-tensor scale × fused param × 在线量化。三个条件缺一不可。

逐方法实证：scale 粒度与缓冲需求

以下基于 vLLM/SGLang 源码逐方法核实。关键发现：所有"per-tensor"实际都是 per-expert 或 per-param（dense），不存在跨全部 expert 的全局 scale。缓冲量始终很小（几 MB/pair），per-expert eager 缓冲完全够用。

weight_amax(flatten(1), dim=-1) → shape [E]		 YES 同一 expert 的 w1+w3 ~几 MB / expert ④ eager

源码证据：vLLM online/fp8.py:578 — w13_amax = weight_amax(layer.w13_weight.flatten(1), dim=-1)，dim=-1 沿 flattened 的 [hidden] 维取 max，输出 shape [num_experts]，每个 expert 独立。SGLang nvfp4_online.py:519 注释原话："Quantize the gated pair together so w1/w3 share one amax-derived per-tensor FP32 scale, matching the serialized NVFP4 convention." —— 缓冲粒度 = 1 个 expert 的 1 对 w1+w3。
结论：buffer 需求是 per-tensor scale × fused pair × 在线量化 三者交叉的数学必然——但实际缓冲量始终是 per-expert 粒度（几 MB），可以在 weight_loader 内 eager 解决（SGLang 已验证），不需要整模型级别的 staging buffer。Block FP8 / MXFP4 / MXFP8 / INT8 每个 block/channel 独立算 scale，到一个 shard 就能量化一个 shard，完全没有这个问题。详见 Per-Param Copy 分类 · ④。
